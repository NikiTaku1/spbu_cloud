# Приложение для обработки вычислений с использованием RabbitMQ

## 1. Описание проекта

Данный проект представляет собой распределённое приложение для выполнения арифметических операций с использованием брокера сообщений RabbitMQ.

Приложение состоит из двух основных компонентов:
- **Producer** — генерирует задания на вычисление и отправляет их в RabbitMQ.
- **Consumer** — получает задания из RabbitMQ, выполняет вычисления и записывает результаты или ошибки в журнал.

Для запуска всех компонентов используется Docker Compose.

## 2. Архитектура и принцип работы

Взаимодействие компонентов происходит следующим образом:

1. Producer каждые 5 секунд генерирует задание с двумя случайными числами и арифметической операцией.
2. Каждому сообщению присваивается уникальный идентификатор.
3. Producer отправляет сообщение в RabbitMQ через Direct Exchange с именем `calculations`.
4. Для маршрутизации используются routing keys:
   - `calc.add`
   - `calc.subtract`
   - `calc.multiply`
   - `calc.divide`
5. RabbitMQ направляет сообщение в соответствующую очередь.
6. Consumer получает сообщение, выполняет вычисление и записывает результат в журнал `logs/consumer.log`.
7. При успешной обработке Consumer подтверждает получение сообщения с помощью `ACK`.
8. Если при обработке возникает ошибка, например деление на ноль, Consumer отклоняет сообщение с помощью `NACK` без повторной постановки в очередь.
9. RabbitMQ перенаправляет ошибочное сообщение в Dead Letter Queue (DLQ) с именем `calculations.dlq`.

## 3. Поддерживаемые операции

| Операция | Назначение |
|---|---|
| `add` | Сложение |
| `subtract` | Вычитание |
| `multiply` | Умножение |
| `divide` | Деление |

## 6. Запуск проекта

Для запуска необходимы установленные Docker Engine и Docker Compose.

Перейти в директорию проекта:

```bash
cd ~/rabbitmq-project
```

Собрать Docker-образы и запустить все сервисы:

```bash
docker compose up --build -d
```

Проверить состояние контейнеров:

```bash
docker compose ps
```

Все три сервиса должны иметь статус `Up`, а RabbitMQ — статус `healthy`.

## 7. Тестирование работы приложения

### 7.1. Проверка Producer

Просмотреть сообщения, отправляемые Producer:

```bash
docker compose logs -f producer
```

Producer должен периодически генерировать задания и отправлять их в RabbitMQ.

### 7.2. Проверка Consumer

Просмотреть работу Consumer:

```bash
docker compose logs -f consumer
```

Consumer должен получать сообщения, выполнять арифметические операции и выводить результаты обработки.

### 7.3. Проверка журнала

Посмотреть сохранённые результаты и ошибки:

```bash
cat logs/consumer.log
```

Успешная обработка отображается с уровнем `SUCCESS`, ошибки — с уровнем `FAILED`.

### 7.4. Проверка очередей RabbitMQ

Выполнить команду:

```bash
docker compose exec rabbitmq rabbitmqctl list_queues name messages
```

Должны отображаться очереди:

- `calculations.add`
- `calculations.subtract`
- `calculations.multiply`
- `calculations.divide`
- `calculations.dlq`

### 7.5. Проверка Dead Letter Queue

Producer может генерировать задания на деление с нулевым делителем.

Consumer обнаруживает ошибку деления на ноль, записывает её в журнал и отклоняет сообщение без повторной постановки в очередь.

Проверить количество сообщений в DLQ:

```bash
docker compose exec rabbitmq rabbitmqctl list_queues name messages
```

В очереди `calculations.dlq` должны появляться сообщения, которые не удалось обработать.

### 7.6. Веб-интерфейс RabbitMQ

Веб-интерфейс брокера доступен по адресу:

http://localhost:15672

Данные для входа:

- Логин: `appuser`
- Пароль: `apppass`

В интерфейсе можно просматривать очереди, сообщения и состояние RabbitMQ.

## 8. Остановка приложения

Остановить контейнеры:

```bash
docker compose down
```

Для остановки контейнеров и удаления тома с данными RabbitMQ:

```bash
docker compose down -v
```

**Внимание:** команда `docker compose down -v` удаляет сохранённые данные брокера.
