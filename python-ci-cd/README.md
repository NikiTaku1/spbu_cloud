# Python CI/CD Project

## 1. Описание проекта

В качестве примера создано простое Python-приложение с арифметическими операциями. Для проекта настроены статический анализ кода, автоматическое тестирование, сборка Docker-образа и его публикация в Docker Hub.

Основная цель проекта — продемонстрировать работу CI/CD pipeline, автоматизирующего проверку качества кода и публикацию приложения в контейнерном виде.

В проекте предусмотрены два варианта настройки CI/CD:
- **GitHub Actions** — основной вариант, который был настроен и запущен в рамках проекта.
- **GitLab CI/CD** — альтернативный вариант конфигурации, который был в задании и который можно использовать при подключении репозитория к GitLab, но это не проверялось.

## 3. Созданные компоненты

### 3.1. Python-приложение

В папке `app/` находится основное приложение `main.py`.

Реализованы следующие функции:
- `add(a, b)` — сложение;
- `subtract(a, b)` — вычитание;
- `multiply(a, b)` — умножение;
- `divide(a, b)` — деление с проверкой деления на ноль.

### 3.2. Автоматические тесты

В папке `tests/` находится файл `test_main.py`.

Для тестирования используется библиотека Pytest.

Создано пять тестов:
1. Проверка сложения.
2. Проверка вычитания.
3. Проверка умножения.
4. Проверка деления.
5. Проверка обработки деления на ноль.

### 3.3. Статический анализ кода

Для проверки качества и оформления Python-кода используется Flake8.

Анализируются файлы приложения и тестов.

### 3.4. Файлы зависимостей

Созданы два файла:

- `requirements.txt` — зависимости, необходимые для запуска приложения. Дополнительные runtime-зависимости в текущем проекте отсутствуют.
- `requirements-dev.txt` — инструменты разработки и проверки: Pytest и Flake8.

### 3.5. Docker

Создан `Dockerfile`, который:
- использует базовый образ Python 3.12;
- задаёт рабочую директорию контейнера;
- устанавливает зависимости приложения;
- копирует исходный код;
- запускает Python-приложение.

Также создан `.dockerignore`, исключающий ненужные файлы и директории из Docker-контекста сборки, включая виртуальное окружение, кэш Python и тесты.

## 4. Настройка CI/CD

### 4.1. Основной вариант — GitHub Actions

Для автоматизации процессов CI/CD используется GitHub Actions.

Конфигурация находится в файле:

`.github/workflows/ci-cd.yml`

Pipeline запускается при изменениях в ветке `main` и при создании Pull Request в эту ветку. Для проекта также настроены фильтры путей, чтобы запускать workflow при изменениях файлов приложения или самой конфигурации.

Pipeline состоит из трёх задач.

**1. Static Analysis**

- Подготовка окружения Python 3.12.
- Установка зависимостей для разработки.
- Запуск Flake8.
- Проверка качества и оформления кода.

**2. Automated Tests**

- Подготовка окружения Python 3.12.
- Установка зависимостей.
- Запуск Pytest.
- Проверка работоспособности функций приложения.

**3. Docker Build and Push**

- Запускается после успешного завершения статического анализа и тестирования.
- Выполняет сборку Docker-образа.
- Авторизуется в Docker Hub.
- Публикует образ с тегом `latest` и тегом, содержащим SHA коммита.

Сборка и публикация Docker-образа выполняются только при push в ветку `main`.

Для авторизации в Docker Hub в настройках GitHub Repository Secrets добавлены:
- `DOCKERHUB_USERNAME` — имя пользователя Docker Hub.
- `DOCKERHUB_TOKEN` — токен доступа Docker Hub.

### 4.2. Альтернативный вариант — GitLab CI/CD

Для проекта также предусмотрена альтернативная конфигурация CI/CD — `.gitlab-ci.yml`.

Её можно использовать, если подключить репозиторий к GitLab и настроить GitLab CI/CD.

В отличие от GitHub Actions, GitLab использует собственный механизм выполнения pipeline на основе GitLab Runner.

Файл `.gitlab-ci.yml` размещается в корневой директории репозитория.

В нём предусмотрены следующие этапы:

1. **Check** — статический анализ кода с помощью Flake8 и запуск тестов Pytest.
2. **Build** — сборка Docker-образа и публикация в Docker Hub.

Сборка Docker-образа выполняется только после успешного завершения проверок и для ветки `main`.

Для работы альтернативной конфигурации необходимо:
- подключить репозиторий к GitLab;
- добавить переменные `DOCKERHUB_USERNAME` и `DOCKERHUB_TOKEN` в Settings → CI/CD → Variables;
- настроить GitLab Runner с поддержкой Docker-in-Docker.

Таким образом, проект можно использовать как с GitHub Actions, так и с GitLab CI/CD. При переходе на GitLab Python-приложение, тесты и Dockerfile остаются без изменений — меняется только конфигурация pipeline и способ его запуска.

**Важно:** GitHub Actions является основным проверенным вариантом проекта. Конфигурация GitLab представлена как альтернативный вариант и требует отдельного запуска и проверки после подключения репозитория к GitLab.

## 5. Docker Hub

Для хранения и распространения Docker-образа используется Docker Hub.

Создан публичный репозиторий:

`nikitaku1/python-ci-cd`

После успешного выполнения CI/CD pipeline в репозиторий публикуются два тега:
- `latest` — последняя версия образа;
- SHA коммита — версия, связанная с конкретным изменением в репозитории.

### Загрузка Docker-образа

```bash
docker pull nikitaku1/python-ci-cd:latest
```

### Запуск контейнера

```bash
docker run --rm nikitaku1/python-ci-cd:latest
```

## 6. Локальный запуск проекта

### Клонирование репозитория

```bash
git clone https://github.com/NikiTaku1/spbu_cloud.git
cd spbu_cloud/python-ci-cd
```

### Создание виртуального окружения

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### Установка зависимостей

```bash
pip install -r requirements-dev.txt
```

### Запуск приложения

```bash
python -m app.main
```

### Запуск тестов

```bash
PYTHONPATH=. pytest -v
```

### Статический анализ

```bash
flake8 app tests --max-line-length=88
```

## 7. Локальная сборка Docker-образа

Сборка образа:

```bash
docker build -t python-ci-cd .
```

Запуск контейнера:

```bash
docker run --rm python-ci-cd
```
