# Python CI/CD Application

## 1. Описание проекта

**Python CI/CD Application** — учебный проект, демонстрирующий разработку Python-приложения, автоматизацию его тестирования, статический анализ исходного кода, контейнеризацию и настройку CI/CD с использованием GitHub Actions и Docker.

Проект размещён в отдельной папке `python-ci-cd` основного репозитория `spbu_cloud`.

Он состоит из двух основных частей:

1. Python-приложение, реализующее базовые арифметические операции.
2. Инфраструктура CI/CD, обеспечивающая автоматическую проверку качества кода, запуск тестов, сборку Docker-образа и его публикацию в Docker Hub.

**Цель проекта** — продемонстрировать автоматизацию процессов разработки, проверки, сборки и доставки программного обеспечения.

## 2. Что было создано в рамках проекта

В ходе выполнения проекта были разработаны и настроены следующие компоненты.

### 2.1. Python-приложение

Создано приложение, реализующее четыре арифметические операции:

- Сложение двух чисел.
- Вычитание двух чисел.
- Умножение двух чисел.
- Деление двух чисел.

Предусмотрена обработка деления на ноль с помощью исключения `ValueError`.

### 2.2. Автоматические тесты

Создан набор автоматических тестов с использованием Pytest.

Реализовано пять тестов, проверяющих:

- Корректность сложения.
- Корректность вычитания.
- Корректность умножения.
- Корректность деления.
- Обработку деления на ноль.

### 2.3. Статический анализ кода

Подключён Flake8 для проверки качества исходного Python-кода.

Настроена проверка файлов приложения и тестов с ограничением длины строки в 88 символов.

### 2.4. Виртуальное окружение

Для локальной разработки создано изолированное виртуальное окружение Python `.venv`.

Оно позволяет устанавливать зависимости проекта отдельно от системного Python.

Виртуальное окружение используется локально и не включается в GitHub-репозиторий.

### 2.5. Docker-контейнеризация

Создан `Dockerfile` на основе официального образа `python:3.12-slim`.

Настроены:

- Сборка Docker-образа.
- Запуск приложения внутри контейнера.
- Использование отдельного рабочего каталога `/app`.
- Установка необходимых зависимостей.
- Исключение ненужных файлов из контекста сборки с помощью `.dockerignore`.

### 2.6. CI/CD через GitHub Actions

Создан файл конфигурации:

`.github/workflows/ci-cd.yml`

Он расположен в корне основного репозитория `spbu_cloud`, а не внутри папки проекта.

Настроены три этапа автоматизации:

1. **Static Analysis** — статический анализ кода с помощью Flake8.
2. **Automated Tests** — автоматическое тестирование с помощью Pytest.
3. **Docker Build and Push** — сборка и публикация Docker-образа в Docker Hub.

Pipeline запускается при изменениях в ветке `main`, затрагивающих папку `python-ci-cd` или файл конфигурации workflow, а также при Pull Request в `main` с такими изменениями.

### 2.7. GitHub Secrets

Для безопасной авторизации GitHub Actions в Docker Hub настроены два секрета:

- `DOCKERHUB_USERNAME` — имя пользователя Docker Hub.
- `DOCKERHUB_TOKEN` — персональный токен доступа Docker Hub.

Секреты хранятся в настройках GitHub и не прописываются непосредственно в исходном коде.

### 2.8. Docker Hub

Создан публичный репозиторий Docker Hub:

`nikitaku1/python-ci-cd`

Настроена автоматическая публикация Docker-образа после успешного прохождения статического анализа и тестов.

Используются два тега:

- `latest` — последняя опубликованная версия.
- Git commit SHA — версия, соответствующая конкретному коммиту.

## 5. Требования для локального запуска

Для работы с проектом необходимы:

- Python 3.12 или совместимая версия.
- pip.
- Docker Engine (для запуска приложения в контейнере).
- Git (для клонирования репозитория).

Разработка и локальная проверка выполнялись в Ubuntu под WSL2 с установленным Docker Engine без использования Docker Desktop.

## 6. Получение проекта

Клонирование основного репозитория:

```bash
git clone https://github.com/NikiTaku1/spbu_cloud.git
```

Переход в каталог проекта:

```bash
cd spbu_cloud/python-ci-cd
```

## 7. Локальный запуск приложения

### Шаг 1. Создание виртуального окружения

```bash
python3 -m venv .venv
```

### Шаг 2. Активация виртуального окружения

Linux / Ubuntu / WSL2:

```bash
source .venv/bin/activate
```

Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

### Шаг 3. Установка зависимостей

Установка зависимостей приложения:

```bash
pip install -r requirements.txt
```

Установка инструментов разработки и тестирования:

```bash
pip install -r requirements-dev.txt
```

### Шаг 4. Запуск приложения

```bash
python -m app.main
```

Ожидаемый результат:

```text
Python CI/CD application
2 + 3 = 5
5 - 2 = 3
4 * 3 = 12
10 / 2 = 5.0
```

## 8. Автоматическое тестирование

Для тестирования приложения используется Pytest.

Запуск тестов:

```bash
PYTHONPATH=. pytest -v
```

Переменная `PYTHONPATH=.` позволяет Python находить пакет `app` при запуске тестов.

Тестирование охватывает все четыре арифметические операции и обработку деления на ноль.

Ожидается успешное прохождение всех пяти тестов.

## 9. Статический анализ кода

Для проверки качества исходного кода используется Flake8.

Запуск проверки:

```bash
flake8 app tests --max-line-length=88
```

Если ошибок нет, Flake8 завершает выполнение успешно.

## 10. Сборка и запуск Docker-контейнера

В проекте используется Dockerfile на основе `python:3.12-slim`.

Все команды данного раздела выполняются из каталога `python-ci-cd`.

### Шаг 1. Сборка Docker-образа

```bash
docker build -t python-ci-cd:local .
```

### Шаг 2. Проверка созданного образа

```bash
docker images
```

### Шаг 3. Запуск контейнера

```bash
docker run --rm python-ci-cd:local
```

Контейнер запускает Python-приложение, выводит результаты арифметических операций и завершает работу.

## 11. CI/CD с использованием GitHub Actions

Конфигурация автоматизации находится в корне основного репозитория:

```text
spbu_cloud/.github/workflows/ci-cd.yml
```

Workflow запускается при:

- Push в ветку `main` с изменениями в `python-ci-cd/**` или `.github/workflows/ci-cd.yml`.
- Pull Request в ветку `main` с изменениями в указанных путях.

### Этап 1. Static Analysis

На первом этапе:

1. Выполняется получение исходного кода.
2. Настраивается Python 3.12.
3. Устанавливаются зависимости разработки.
4. Запускается Flake8.

Цель этапа — проверить качество и оформление исходного кода.

### Этап 2. Automated Tests

На втором этапе:

1. Выполняется получение исходного кода.
2. Настраивается Python 3.12.
3. Устанавливаются зависимости.
4. Запускаются автоматические тесты Pytest.

Цель этапа — проверить корректность работы приложения.

### Этап 3. Docker Build and Push

Третий этап выполняется только при Push в ветку `main` и после успешного завершения двух предыдущих этапов.

Последовательность действий:

1. Настраивается Docker Buildx.
2. Выполняется авторизация в Docker Hub.
3. Собирается Docker-образ из каталога `python-ci-cd`.
4. Образ публикуется в Docker Hub.

Публикуются два тега:

- `latest`.
- Git commit SHA.

Если статический анализ или тестирование завершаются ошибкой, этап публикации Docker-образа не запускается.

## 12. Настройка GitHub Secrets

Для авторизации в Docker Hub используются два секрета:

| Название | Назначение |
|---|---|
| `DOCKERHUB_USERNAME` | Логин пользователя Docker Hub |
| `DOCKERHUB_TOKEN` | Персональный токен Docker Hub |

Секреты добавляются в настройках GitHub:

`Settings → Secrets and variables → Actions → New repository secret`.

Это позволяет безопасно использовать учётные данные при выполнении CI/CD без хранения токенов в исходном коде.

## 13. Получение и запуск опубликованного Docker-образа

https://hub.docker.com/repository/docker/nikitaku1/python-ci-cd/general

Запуск контейнера:
